# 田口産業システム ロードマップ

## Direction

最初に、現在確定している課題である「現場から本社への発注受付」をオンライン化します。その後の業務システム化は、初期Proposalを設計資産として利用しながら、関係者への要求確認を経て段階的に判断します。

ロードマップは、旧Proposalをそのまま実装順序として採用するものではありません。各段階へ進む条件は、実業務上の必要性が確認されることです。

## Horizons

### Horizon 1 — 発注受付のオンライン化

現行MVPです。

- Webフォームによる発注入力
- 本社へのメール通知
- 発注書PDF生成
- 既存受注工程への引き継ぎ

必要に応じて、PDFの受注用PCへの自動保存・自動印刷を追加します。

### Horizon 2 — 受注側オペレーションの改善

MVP運用後に、実際の受注処理で発生した負荷を観察して判断します。候補には以下があります。

- 受付履歴の検索・管理
- 再送・再印刷
- 処理状況の簡易管理
- 発注内容の訂正・取消運用
- PDF保存・印刷の自動化強化

ここでは現場と本社の境界を改善し、業務全体の再設計には踏み込みません。

### Horizon 3 — 業務管理システムへの拡張

関係者の要求が確認できた場合にのみ検討します。

初期Proposalで検討済みの候補には以下があります。

- 一般注文・買掛注文
- 現場別発注管理
- 承認フロー
- 発注・注文履歴管理
- 現場別原価集計
- 権限管理
- 価格履歴管理
- 管理ダッシュボード
- CSV等によるデータ出力

### Horizon 4 — サプライチェーン連携

業務管理システムの必要性と運用が確立した後の将来候補です。

- 発注先・仕入先ポータル
- 納期回答
- 出荷登録
- 在庫連携
- 会計連携
- BI分析
- FAX API等の外部連携

## Milestones

1. **M1: オンライン発注受付成立** — 代表発注をフォームから送信し、本社でメールとPDFを受領できる。
2. **M2: 既存業務への安定接続** — 実運用上の受付・保存・印刷が安定し、FAX・電話依存を削減できる。
3. **M3: 次段階の要求確認** — Horizon 2以降について、利用者・管理者・関係者から必要性と優先度を確認する。
4. **M4以降: 承認済み機能の段階導入** — 要求確認済みの項目だけをPlanへ昇格して実装する。

## Dependencies

- Horizon 1は、発注フォーム項目、通知先、PDF様式、受付運用の確定に依存します。
- PDF自動保存・自動印刷は、受注用PC・OS・ネットワーク・プリンタ・セキュリティ条件に依存します。
- Horizon 2以降は、MVPの利用実績と業務上の課題観察に依存します。
- Horizon 3以降は、元請けを含む関係者の要求確認と合意に依存します。
