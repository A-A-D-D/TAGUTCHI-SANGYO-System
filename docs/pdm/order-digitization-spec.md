# 田口産業 発注オンライン化 現行仕様

## Purpose

現場から本社（管理側）への発注を、FAX・電話を中心とした運用からオンライン入力へ置き換えます。

本仕様の目的は、既存業務を全面的に再設計することではなく、発注情報の入口をオンライン化し、現行の受注業務へ確実に接続することです。

## Scope

### MVP

MVPの対象は以下です。

1. 現場担当者がWebフォームから発注内容を入力できること。
2. 送信された発注内容を本社側へメールで通知できること。
3. 同一内容から発注書PDFを生成できること。
4. 本社側がメールおよびPDFを用いて、既存の受注処理を継続できること。

### MVPに含めないもの

以下は現時点の確定要求ではないため、MVPの必須要件には含めません。

- ECとしての商品購入体験全般
- 一般注文と買掛注文を包括する注文基盤
- 現場別原価管理
- 承認ワークフロー
- 管理ダッシュボード
- 高度な注文・納品ステータス管理
- 仕入先ポータル
- 会計・在庫・BI連携

これらは不要と確定した機能ではなく、将来提案候補として別文書で管理します。

### 実装してよい追加の一手

MVPの目的を変えず、既存業務への接続を改善する範囲として、次を追加可能とします。

- 生成した発注書PDFを受注用PCへ自動保存する。
- 保存されたPDFを所定のプリンタへ自動印刷する。

この追加は、受注側の既存運用・端末・プリンタ・セキュリティ条件を確認した上で導入します。

## Requirements

### R1. 発注入力

- 発注者が必要事項をオンラインで入力できること。
- 必須項目の未入力や形式不正を送信前に検知できること。
- 入力内容を送信前に確認できることが望ましいです。

### R2. 通知

- 正常受付時に、本社側の所定の宛先へ発注内容をメール送信できること。
- メール送信失敗を正常受付として扱わない、または失敗を検知・再処理できること。

### R3. PDF

- 発注内容から、人が確認・保存・印刷できる発注書PDFを生成できること。
- メール内容とPDF内容の主要項目が一致すること。
- 同一発注を識別できる発注番号または同等の識別子を持つこと。

### R4. 既存業務との接続

- 本システム導入のために、本社側の受注処理全体を変更することを必須としません。
- MVPでは「オンラインで受けた情報を、既存の受注工程へ渡せること」を完成条件とします。

### R5. 監査可能性

- 発注の受付日時と内容を後から確認できる状態を維持します。
- 送信・PDF生成の成否を調査できるログまたは記録を保持します。

## Boundary

現在のMVPは「現場 → 本社」の発注受付境界を対象とします。本社から仕入先への発注、仕入先からの納期回答、在庫・会計等への連携は、要求確認後に別フェーズとして判断します。

## Acceptance basis

MVPは、代表的な発注をフォームから投入し、本社側でメールとPDFの双方を受領して既存業務へ引き継げることを確認した時点で、主要機能が成立したと判断します。
